# CI、产出物与 CD 领域设计

## 1. 文档状态与核心路径

提议，依据 [ADR-0007](decisions/0007-ci-artifact-cd-separation.md)，尚未实现。当前基线为 `main@875cbd7` / epoch 8（PR #38 已合并）；下面的模型名、路由和界面均为目标契约，不是当前 API 文档。

```text
应用类型 Java ── CI 模板：Maven 构建、Gradle 构建、构建并制作镜像
                    ↓ 应用选择一个已发布版本，提供仓库/构建参数
应用 ── CI 运行 ── 产出物 A（JAR 或 OCI 镜像，固定摘要）
                    ├─ CD 运行：测试环境 ── 直接部署 A
                    └─ CD 运行：生产环境 ── 加入 Agent ── 派生产出物 B ── 部署 B
```

环境不决定是否重新构建。用户也可以不执行新 CI，直接选择历史可用产出物发起 CD。生产审批可作为后续步骤能力或模板变体，但没有审批执行器时不能运行该模板；本轮不宣称已实现审批。

## 2. 模型与职责

| 模型 | 归属与主要数据 | 不承担的职责 |
| --- | --- | --- |
| ApplicationType | 稳定代码、名称、启用状态；一个类型关联多套 CI 模板 | 不固定 Java/Python 枚举，不替代部署目标 |
| CITemplate / Version | 一个所属类型、步骤规范、参数 schema、命名输出契约、版本和校验和 | 不内置某个应用仓库或生产环境凭据 |
| ApplicationCIBinding | 应用、固定模板版本、仓库/目录等参数、revision | 不复制步骤列表，不依赖 AppConfig |
| BuildRun | 应用、类型快照、CI 版本、源 ref 与解析后的 commit、参数快照、状态 | 不以“生产/测试”等环境作为构建必填项 |
| Artifact | 应用、类型、内容身份、生产运行/步骤/attempt、命名输出、父引用 | 不等于日志中的文件名、tag 或 Output JSON |
| CDTemplate / Version | 输入产物槽位、目标类型、加工/部署步骤、参数 schema、版本 | 不强制对应一种语言 |
| ApplicationCDTargetBinding | AppConfig、固定 CD 版本、环境参数、revision | 不修改已提交任务或历史 CI |
| DeploymentRun | AppConfig、输入产物集合、CD 版本、实际部署产物、状态 | 不隐式重新跑 CI，不部署浮动 latest |

类型变更须检查应用当前 CI 绑定，必须在同一事务改绑到兼容模板，或明确解除绑定后再变更；不能静默沿用旧类型模板。停用类型/模板阻止新绑定和新运行，但历史可读、在途任务按快照恢复。已有 `dev_language`、`dev_language_rules`、`code_package_type` 是迁移线索，不作为新身份主键。

## 3. 模板、版本和插槽

集中管理入口提供“应用类型”“CI 模板”“CD 模板”。管理员维护模板，普通应用操作者选择允许的版本并填写参数。CI 首版每个应用一个活动绑定，类型下可以有任意多套候选模板；需要构建变体时显式改绑，历史构建不受影响。

模板草稿可编辑；发布时验证全部步骤和输入输出连线，创建不可变版本。绑定必须指定 version_id，用 expected_revision 做 CAS；发布新版本不自动升级已绑定应用，旧版本仍可显式选择，停用策略另行校验。运行创建时冻结版本、参数及绑定 revision；执行中禁止临时编辑。

每个步骤仍由精确 `uses@version` 注册，采用串行执行。新增类型化命名输入/输出槽位：输入只能来自运行输入或前面步骤的已声明输出，不允许向后引用、循环、未知槽位或任意表达式。可接受多个输入与多个输出，但有显式数量/大小上限；具体数值在 W11-A 的 schema/API PR 中冻结并测试。

- Java 模板示例：源码 → Maven → 测试 → 发布 JAR；或源码 → Gradle → 镜像构建 → 发布 OCI 镜像。
- Python 模板示例：源码 → 测试 → 打包 wheel；或源码 → 依赖安装与测试 → 镜像构建。
- CD 示例：JAR + Agent 版本参数 → 镜像加工 → OCI 镜像 → Kubernetes 部署；或 OCI 镜像 → 加 Agent → 派生镜像 → 部署。

上述是真实适配器未来要实现的组合，不能把 Noop 命名为 Maven 后宣称完成构建。首个可交互版本只能使用有明确模拟标识的 CI/CD 模板验证业务链路。

参数优先级为模板默认值 < CI 应用绑定值或 CD 环境绑定值 < 模板明确允许的本次覆盖值；未知字段拒绝。字段可声明禁止覆盖。集群身份、Secret 引用权限、步骤结构和输入 artifact_id 不通过普通参数覆盖。CI 不得读取 CD 的生产凭据；Secret 解析结果不写入任务快照或公开响应。

## 4. 产出物契约

### 4.1 内容身份与存储

产物拥有服务端 artifact_id、应用归属、kind、media_type、摘要算法和值、创建时间、生产 task/step/attempt/output_name；文件还包含安全文件名、大小、受管存储对象的固定版本，镜像包含受管 registry/repository 和 manifest digest（多架构镜像使用固定 index digest）。可记录人类可读版本与 tag，但部署只按不可变摘要/对象版本解析。

首批类型契约覆盖 OCI 镜像及包文件（JAR、wheel 通过 media_type 区分）；支持能力以已安装的适配器为准。元数据与二进制分离，不把 JAR 或镜像层塞进 MySQL。下载授权、对象存储和 registry 凭据由受管集成提供；公共 API 只返回白名单元数据，不暴露带凭据 URL、opaque reference 或临时签名。

同样内容可有不同来源记录，不能只按 digest 全局合并并抹掉应用归属。首版只允许同一应用产物进入该应用的 CD；跨应用引用即使知道 ID 也拒绝。模拟产物只能进入模拟 CD，不能被真实部署执行器消费。

### 4.2 可用性与提交边界

候选产物由受信执行器报告，但 Ares 必须校验声明槽位、类型、受管来源、摘要格式与可验证内容身份。浏览器不能伪造“构建成功”或提交任意 URL 登记产物。

工作流与单个步骤成功不是同一门禁：产物生产步骤成功后，候选记录仍不可供其他运行选择；只有生产运行满足成功条件并完成全部必需质量门禁，最终事务才发布为可选产物。首版允许 `succeeded`，不允许 failed/timed_out/outcome_unknown/cancelled 或 `succeeded_with_warnings` 自动发布。对质量门禁使用 stop；CI/CD 加工流程不能用 continue 绕过发布门禁。当前运行可消费已成功前置步骤的候选产物，外部运行不可见。

登记与当前步骤结果使用同一 lease/fencing 事务；唯一约束为生产任务 + 步骤 + attempt + 输出名。相同身份、相同内容重放返回原记录；不同内容冲突并停止，绝不覆盖。运行终态与产物可选状态在同一事务提交，崩溃后可幂等恢复。

外部上传不在数据库事务内：执行器先通过稳定执行键创建/查找受管对象，再登记。上传成功但回写失败时重用同一 attempt 及引用对账，不能盲目再上传/重建。数据库 fencing 只保护本地提交，不能宣称外部 exactly-once。无主外部对象只记录待核查，不在首版自动删除。

### 4.3 派生、发布与回退

加工产生新的 artifact_id 和内容身份，parents 保存输入产物及槽位，记录所用 Agent 版本、模板版本和生产 attempt；父关系只指向已有产物，禁止环，保留完整来源链。Agent 必须固定版本/摘要，不能在重放时获取浮动 latest。相同字节的再加工仍保留本次来源关系。

CD 创建时冻结输入集合。后续模板改绑、CI 新构建或 tag 移动都不改变它。部署步骤显式声明实际消费的产物槽位；只有执行器确认成功后保存“实际部署成功”的产物引用，提交/超时不算成功。

首版回退是新建 CD 运行并选择历史产物，而非修改旧任务；若要求原样回退，应选择最终派生镜像，使用不再加工的兼容部署模板。选择原始镜像再次加 Agent 属于新加工，不保证复现旧结果。存储缺失或摘要不匹配时禁止发布，不自动重新跑 CI。禁止自动清理被在途或历史部署引用的元数据；完整保留/撤销/垃圾回收策略另立计划，不能按使用次数随意删除。

## 5. 运行、API 与权限边界

复用现有 task/step/attempt、日志和 lease 机制，新增显式运行种类及类型化上下文。CI 创建目标是 app_id；CD 是 config_id + 命名 artifact_id 集合。不以空环境或伪造 AppConfig 适配旧创建接口。

拟议 API 分组：应用类型目录、CI/CD 模板及版本、应用 CI 绑定、AppConfig CD 绑定、build-runs、deployment-runs、artifacts。具体路径/DTO 在 W11-A 文档及契约测试中冻结，当前 Swagger 不新增未实现接口。

新 CI/CD 创建采用独立版本化语义操作的 Idempotency-Key 回执。摘要覆盖目标、模板版本、预期绑定 revision、用户输入和显式产物 ID；不包含解析后随时间变化的 tag 或配置。先查既有回执再做当前可用性预检，同 key/同摘要重放原任务；改变产物或模板版本返回冲突。数据库事务校验归属、启用状态、版本、输入兼容性并冻结快照，外部源 commit/摘要验证放到有幂等键的执行阶段，不在持锁事务里访问网络。

源 ref 在运行创建时冻结字符串，checkout 首次解析并持久化 commit 后，后续步骤和重试只使用该 commit。无法证明初次 checkout 结果时停止并对账，不因分支移动重新解释为同一构建。UI 分别展示“请求 ref”和“实际 commit”，不能把 ref 当成不可变来源。

权限计划新增类型/模板管理、CI 绑定与构建创建、CD 绑定与部署创建、产物读取；admin 维护全局定义，releaser 使用允许的模板构建和部署，viewer 只读。最终角色映射在 W11-A 列表化并测试；服务端同时校验资源关系，不靠前端筛选。日志仍需 logs.read，参数私密字段仍按工作流权限收紧，外连仍执行 SSRF/重定向/集成绑定校验。SecretResolver 未就绪前不得增加通用凭据输入能力。

## 6. Web 交互目标

1. 管理入口：维护应用类型；进入 Java 查看 Maven/Gradle 等 CI 模板，编辑步骤、参数与输出槽位，发布新版本；CD 页面独立管理输入契约、加工与部署步骤。
2. 应用详情：基础信息选择类型；CI 页选择版本、配置仓库并发起构建；构建历史能查看固定 commit、步骤日志和产物，无需选择发布环境。
3. 产物页：按应用、kind、构建筛选可用版本；详情显示生产步骤/attempt、父子关系及部署去向，候选/缺失/模拟状态明确区分。
4. 应用环境页：选择 CD 模板及环境参数；发布时选择兼容产物，预检展示输入→加工→最终部署路径，不兼容选择给出具体原因。
5. CD 历史：同时展示原始输入与最终部署产物，展示加工日志、目标环境与结果；已有历史版本可发起新的受控部署，不出现伪取消或伪审批入口。

空状态引导先建类型/模板或使用模拟 Demo。无模板、无产物、无适配器应明确展示缺失项，而不是回退触发旧 Jenkins 流程。

## 7. 兼容与验收入口

旧 v1 Jenkins 和 epoch 8 的整条 v2 工作流继续按原引擎/快照运行，保留历史及旧幂等回执。新模型是显式 opt-in，前端标记旧模式，不隐式双写、双执行或失败后 fallback。具体分步迁移和验收矩阵见[实施计划](../plans/ci-artifact-cd-roadmap.md)。
