### 2.1 A：模型与契约

2026-09-11 开始实施，拆为 A1 模板契约与无副作用校验、A2 类型/模板持久化与版本 CAS、A3 管理接口及权限矩阵。A1 不写数据库、不登记产物、不启动任务；其校验成功仅表示结构合法，不能当作可执行或已发布模板。A2/A3 仍未开始，完整 W11-A 尚未交付。

| 增量 | 状态 | 范围 |
| --- | --- | --- |
| A1 | 开发中 | 独立 CI/CD 规范、类型化槽位、前序引用、参数约束、校验 API 与回归测试 |
| A2 | 未开始 | 应用类型目录、集中模板草稿与不可变版本、schema 与最小权限迁移 |
| A3 | 未开始 | 类型/模板管理 API、版本/CAS、权限矩阵及集成验收 |

- [ ] 定义应用类型稳定身份与启停策略，种子含 Java/Python，但支持自定义类型。
- [ ] 建立集中 CI/CD 模板草稿、发布版本及绑定升级策略；发布版本不可变。
- [ ] 定义产物类型、命名槽位、前序引用、参数可覆盖范围、批量/大小上限与 schema_version。
- [ ] 在实现 PR 中补充精确数据库表/索引/约束、API 请求响应、权限到角色的映射和错误码。
- [ ] 针对所有新增对象补迁移 manifest、数据契约、checksum/fingerprint、最小权限账号矩阵；不能修改已发布 epoch 1～8。

### 2.2 B：独立运行与兼容框架

- [ ] CI 创建使用 app_id，不要求配置环境；CD 使用 config_id、输入 artifact_id 集合、固定模板版本与 revision。
- [ ] 复用 Worker/attempt，而非复制两个调度器；用明确运行种类和上下文识别新旧路径。
- [ ] 新创建操作采用独立语义命名空间的永久回执，覆盖原子快照、稳定顺序锁、重复请求及陈旧 revision。
- [ ] 在 C 完成前，新产物发布入口保持不可用；缺能力返回明确业务错误，不接受不可执行任务、不伪造产物。
- [ ] 保留旧 API/receipt 和 v1/v2 调度语义，新增 API 不调用旧全流程 fallback。

### 2.3 C：产物状态与步骤交接

- [ ] 候选登记与步骤结果原子提交，唯一身份为运行/步骤/attempt/输出名；重放同内容不重复登记，异内容冲突。
- [ ] 生产运行成功门禁与产物发布原子提交；质量检查失败/警告/不明确不发布。
- [ ] 外部存储读取采用受管引用与内容验证，服务层拒绝客户端任意地址。
- [ ] 构建来源 commit、父产物、加工参数版本及最终实际部署引用可追溯；公开响应按白名单输出。
- [ ] 提供明确模拟标识的文件/镜像产物与加工/部署执行器；模拟产物不得进入真实部署。

### 2.4 D/E：交互、迁移和预览

- [ ] 管理者在统一入口配置类型下多种 CI 组合；应用只选版本与参数。
- [ ] CI 运行、产物、CD 运行分别有列表与详情；CD 显示原始/派生/实际部署产物。
- [ ] 多环境可选不同 CD 模板或参数，不复制 CI、不把 CI 步骤写回 AppConfig。
- [ ] 旧应用默认维持旧模式，提供人工确认的类型映射与绑定操作，记录转换审计。
- [ ] 补齐空库模拟 Demo 与旧库 opt-in 演练，完成下面的全栈验收矩阵。
- [ ] 每次交付继续更新固定 `ares-preview`，保留数据与管理员；只有文档变化时不重建相同业务代码。涉及迁移先停旧 Worker、备份再升级，记录部署 commit 和结果，不直接合并 PR。

### 2.5 F：真实能力门禁

在 F 开发前补充具体适配器选择 ADR，比较现有 Jenkins Adapter 扩展与独立执行平台的成本；产品模型与元数据不得依赖最终平台。选择不是让核心再次强制 Jenkins。

- [ ] 至少验证一种真实 Java CI 组合；Python 模板必须绑定真实能力才能启用，不以占位步骤冒充实现。
- [ ] 真实镜像存储按 digest 解析，Agent 加工产生新摘要并保留原镜像。
- [ ] 在隔离目标环境完成部署与历史最终镜像再部署，验证无需重跑 CI。
- [ ] SecretResolver、权限/审计、SSRF、日志脱敏、执行隔离、外部幂等/取消确认全部过关。
- [ ] W11-A～E 仅代表模型与模拟闭环完成；F 未完成不得宣称真实 Java/Python CI 或生产 CD 可用。

## 3. 数据迁移与兼容策略

### 3.1 Expand：旧数据不猜测

新增结构从后续可用 epoch 追加，具体编号由对应代码 PR 根据当时 main 分配，本轮不抢占 epoch 9。每个迁移可重复、可中断恢复，有完整 manifest、数据契约与 runtime 授权；新版本按实际兼容区间启动。

- `dev_language` 与 `dev_language_rules` 只导出映射清单。明确匹配才可人工确认关联类型；空值、自定义值、大小写碰撞不静默合并，不因缺类型阻止旧应用历史查询。
- 旧 `release_workflows` / versions / `app_config_workflows` 保留为 legacy combined。即使已有 build/deploy category 也不自动拆分、不发布为可跨应用复用的新模板。
- 旧 task/step/attempt、Output、external_ref、幂等 receipt 保持原样。历史镜像字符串不补造成可信 Artifact；首次新 CD 应选择新 CI 产物，不以旧 tag 猜测摘要。
- 在途旧任务继续按其原始快照由明确的旧路径推进；只由兼容的新二进制承接，不允许旧二进制与不兼容新库混写。禁止 shadow 双执行。

### 3.2 Switch：显式 opt-in

管理员检查应用类型、选定 CI 版本、逐个环境选定 CD 版本及参数；预检全部通过后用 CAS 切换应用模式，不自动触发构建或部署。旧模式未转换时保留旧界面与 API。切换后旧创建入口对新请求返回明确冲突，不静默恢复全流程；既有幂等 key 仍按旧 receipt 重放原结果。

转换时若应用仍有活动 legacy 任务，首版阻止切换并列出待排空任务，避免两种发布同时修改同一环境。此门禁是 Ares 内部边界，不宣称排除了人为外部部署。新 CI/CD 历史存在后不支持“一键切回旧模式”；错误配置通过改绑新版本前向修复。

### 3.3 Contract 与恢复

本工作包不删除旧表、旧列或旧 API，不重写历史 migration。移除需要独立使用量审计与弃用计划。每次升级停止旧 API/Worker、备份并验证恢复，升级 schema、刷新 runtime 表级权限，再验证新版本。失败保留故障库；已越过不兼容 epoch 时必须恢复备份与匹配镜像，不能只回退 Git 分支或修改 ledger。

数据库恢复不撤销已经上传的镜像或已提交的外部部署；回退前必须核对外部对象和执行记录，未知结果不自动重试。

## 4. 验收矩阵

| 场景 | 必须证明的结果 |
| --- | --- |
| Java 多组合 / 自定义类型 | 同类型下可选择至少两套 CI 模板；新增类型无需改枚举 |
| CI 不依赖环境 | 没有 AppConfig 的应用可构建并查看产物，不要求集群 |
| 一次构建、多环境 | 同一 artifact_id 可分别创建两个环境 CD，CI 运行数不增加 |
| CD 加 Agent | 派生新产物，父产物摘要未变，最终部署记录指向派生物 |
| 历史再部署 | 固定最终产物配直接部署模板，不重新构建或重做加工 |
| 类型/归属校验 | wheel 不能误入 JAR 槽位；跨应用和模拟→真实输入被服务端拒绝 |
| 模板与来源冻结 | 发布新模板、改绑环境、移动 branch/tag 均不改变已有运行的已解析 commit/digest |
| 质量门禁失败 | 产物生产步骤成功但后续测试失败时，其他运行不能选用该候选产物 |
| 并发与崩溃 | 多 Worker、重复请求、上传后断连、登记后重启不重复任务/产物，不接受陈旧 fencing |
| 安全重试 | 新 attempt 有新执行键；历史产物来源不覆盖；未知结果与超时不触发新外部副作用 |
| 权限和泄漏 | viewer 无法改模板/发起运行；私有引用/Secret 不进入公开 JSON、日志或审计 |
| 旧库兼容 | 旧任务/日志/receipt 可读和重放；转换不猜历史产物、不双执行；旧在途任务阻止切换 |
| 迁移与重启 | 空库、epoch 8 升级、逐 DDL 中断/并发恢复、最小权限账号、稳定持久化数据均通过 |
| 预览与真实能力 | E 的模拟闭环明确标识；F 使用真实 registry/隔离部署目标提供独立验收证据 |

前端每阶段包含组件测试、类型检查、Lint 与构建；后端包含单测、Race、API/RBAC、真实 MySQL 集成。涉及界面联动的 D/E/F 增加浏览器端到端验证；运行时镜像和供应链继续沿用仓库门禁。没有执行的测试必须标明未执行。
